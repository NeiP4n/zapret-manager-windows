# Карта модулей

Структура проекта: **одна ветка (`main`), один Go-модуль (`github.com/zapretmanager/zmwin`),
модули = пакеты**. Ветки и отдельные репозитории на модуль не используются осознанно:
ветка — это линия истории, а не единица поставки, и приложение в ней становится неполным.
Границы модулей проверяет компилятор, а не merge.

## Слои и зависимости

```
cmd/zapret-manager
  └── core ─┬─ zapret ── app ── (stdlib)
            ├─ doh            osx
            ├─ routing ── awg
            ├─ tg ── sysinfo ── zapret
            ├─ byetube
            └─ web ── (все модули + evade)
cli ── web (клиент запущенной службы)
evade ── ничего из internal (независимый модуль диагностики)
```

Правило: зависимости идут **вниз**. `app` и `osx` не знают о своих потребителях; `evade`
не знает ни о чём внутри проекта (поэтому его можно тестировать и переобучать отдельно).
Если появляется импорт «вверх» — это ошибка границы, а не повод для merge.

## Модули

| Модуль | Ответственность | Ключевой контракт | Что можно менять свободно |
|---|---|---|---|
| `app` | пути (`%ProgramData%\ZapretManager`, `ZM_BASE`), `Settings`/`KV`, фоновые `Job`, загрузки, логи | `S()`, `Update()`, `StartJob`, `P()`, `Base`, `Dev` | внутренности загрузок, формат KV |
| `osx` | единственный Windows-слой: процессы, служба, PowerShell, firewall, Job Object | `Run`, `PS`, `ProcStart/Stop`, `Service*`, `Elevate` | всё, что не меняет сигнатуры |
| `zapret` | winws: установка, `BuildArgs`, стратегии, тестер, `RandomBody`/`ValidateBody` | текст стратегии в формате роутера (`state\strategy.txt`) | пресеты, генератор, тестер |
| `zapret2` | winws2 + lua (внутри пакета `zapret`) | то же | — |
| `evade` | диагностика блокировки, план лечения, модель 26→16→3 | `Evidence`, `Classify`, `Scan`, `Plan`, `Model` | признаки, правила, веса (через `genmodel`) |
| `doh` | свой DoH-прокси на 127.0.0.1:53, смена/восстановление DNS | `Apply`, `Shutdown`, `Watch` | провайдеры, кеш |
| `hosts` | пресеты hosts, GeoHide, редактор | `Status`, `Toggle`, `SetFile` | блоки, парсинг |
| `tg` | TG WS Proxy (Go/Rust сборки) | `Install`, `Action`, `Status` | — |
| `awg` | AmneziaWG/WARP, I1-обфускация | `InstallClient`, `Start/Stop`, `Warp*` | — |
| `byetube` | ByeDPI + PAC через `AutoConfigURL` | `Boot`, `Shutdown`, `PAC` | пресеты, PAC |
| `routing` | один mihomo (TUN) для Steer/Forkozz/Mixomo | `Install`, `Boot`, `Stop`, `Tick` | генерация конфига, правила |
| `sysinfo` | системная страница: сеть, QUIC, IPv6, темы | `Get`, `SetTheme`, `LanIP` | — |
| `web` | панель 127.0.0.1:17580, авторизация, JSON API, SPA | `Serve`, `Handler`, `Token`, `Port` | эндпоинты, UI |
| `cli` | консольное меню — клиент API службы | `Menu`, `Status`, `Uninstall` | — |
| `core` | порядок загрузки, планировщик, `Shutdown` | `Run(ctx)`, `Shutdown` | расписание |

## Как менять через ИИ

1. Назови модуль (папку) — правки не должны выходить за неё без причины.
2. Контракт модуля — экспортируемые символы из таблицы; их смена требует правки потребителей
   (обычно `web/api.go` и `core`).
3. После правки: `go vet ./...`, `GOOS=linux go vet ./...`, `go test ./...`,
   для UI — `node --check internal/web/ui/*.js`.
4. Новая системная функция → `app.StartJob` + русские ошибки, изменения обратимы
   (см. `docs/adaptive-core.md`, раздел 4).

## Когда всё-таки делить по-настоящему

Если модулю нужна **своя версия и свой релизный цикл** (например, `evade` с моделью хочется
катать отдельно) — тогда это отдельный репозиторий + `go.mod`, а не ветка. Учесть:
`internal/` нельзя использовать из другого модуля, поэтому пакет придётся перенести из
`internal/evade` в `evade` и поправить импорты в `web`.
